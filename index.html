1. Introducción

La búsqueda con vuelta atrás (backtracking) es una técnica algorítmica fundamental para resolver problemas de satisfacción de restricciones y de optimización combinatoria.

Construye las soluciones de manera incremental y abandona una rama de exploración en cuanto detecta que no puede conducir a una solución válida.

💡

El término "backtrack" fue acuñado por el profesor D. H. Lehmer, de la Universidad de California en Berkeley (NIST, 2021).

2. ¿Qué es la búsqueda con vuelta atrás?

Definición de Dechter (2003)

Es un método de búsqueda completa que recorre en profundidad el espacio de soluciones parciales. Cada paso asigna un valor a una variable adicional y extiende así una solución parcial candidata.

Cuando aparece una variable ninguno de cuyos valores es consistente con la solución parcial actual, se produce un callejón sin salida (dead-end); en ese momento el algoritmo retrocede hasta una variable anterior e intenta asignarle un valor distinto que evite el conflicto.

Analogía de Stanford University (2024)

El algoritmo avanza por un camino tomando decisiones en distintos puntos; si llega a un callejón sin salida, regresa al último punto donde decidió algo y elige otra alternativa, siempre que queden opciones disponibles.

🌳 El árbol de búsqueda

  • Nodo: asignación parcial de valores a variables
  • Raíz: asignación vacía
  • Arista: asignación de un valor a una variable adicional
  • Poda: cuando un nodo viola una restricción, se elimina el subárbol

Esto garantiza que la búsqueda sea completa: si existe una solución, la vuelta atrás la encuentra (Dechter, 2003).

3. Estructura del algoritmo

Gurari (1999) describe el algoritmo como un refinamiento del enfoque de fuerza bruta. Las soluciones se representan mediante vectores (v₁, ..., vₘ) y el algoritmo recorre en profundidad los dominios de esos vectores.

Pseudocódigo del algoritmo

Figura 1 - Pseudocódigo de vuelta atrás 
ALGORITHM try(v1,...,vi)
    IF (v1,...,vi) is a solution THEN
        RETURN (v1,...,vi)
    FOR each v DO
        IF (v1,...,vi,v) is acceptable vector THEN
            sol = try(v1,...,vi,v)
            IF sol != () THEN
                RETURN sol
            END
        END
    END
    RETURN ()

Nota. Adaptado de Gurari (1999).

Espacio de soluciones

Si Sᵢ es el dominio de vᵢ, el producto S₁ × ... × Sₘ constituye el espacio de soluciones del problema.

4. El paradigma «Elegir, Explorar, Deshacer»

Stanford University (2024) sintetiza la vuelta atrás recursiva en tres fases:

1

Elegir

Un bucle considera todos los movimientos posibles y elige uno, ajustando el estado.

2

Explorar

Pasa el estado modificado a la función recursiva para ver si conduce a la solución.

3

Deshacer

Si no funciona, restaura el estado anterior antes de probar la siguiente opción.

⚠️ Consideraciones importantes

  • La vuelta atrás no siempre encuentra el camino más corto.
  • Hay que llevar un registro de los estados ya visitados para no caer en recursión infinita.
  • En el ejemplo del laberinto se usan "migajas de pan" para marcar celdas exploradas.

5. Ejemplo: Generación de Subconjuntos

Para S = {a, b, c}, el conjunto potencia contiene 8 subconjuntos, desde el vacío hasta {a, b, c}. Con cada elemento se toma una decisión binaria: incluirlo o descartarlo.

Código en C++

Figura 2 - Generación de subconjuntos 
#include <iostream>
#include "console.h"
using namespace std;

void fancyPrint(string s) {
    cout << "{";
    for (int i = 0; i < s.length(); i++) {
        cout << s[i];
        if (i != s.length() - 1) {
            cout << ", ";
        }
    }
    cout << "}" << endl;
}

void printSubsets(string soFar, string rest) {
    if (rest.empty()) {
        fancyPrint(soFar);
        return;
    }
    char thisOne = rest[0];
    string newRest = rest.substr(1);
    printSubsets(soFar, newRest);
    printSubsets(soFar + thisOne, newRest);
}

void printSubsets(string s) {
    printSubsets("", s);
}

int main() {
    printSubsets("abc");
    return 0;
}

6. Análisis de Complejidad

⏱️ Complejidad Temporal

En el peor caso es exponencial:

T(n) = k · T(n−1), T(0) = 1 ⟹ T(n) = O(kⁿ)

Para n variables con dominios de tamaño k.

💾 Complejidad Espacial

Lineal — mantiene una sola solución parcial en memoria.

Solo almacena el camino raíz → nodo actual (Gurari, 1999).

📌 Observaciones

  • La fórmula O(kⁿ) es un modelo simplificado: supone dominios iguales, costo constante y ausencia de poda.
  • El rendimiento real depende de la estructura del problema, sus restricciones y estrategias de poda (Dechter, 2003).
  • En generación de subconjuntos, el número de llamadas es O(2ⁿ).

7. Técnicas de Optimización

🔍 Forward Checking

Examina los dominios restantes inmediatamente después de cada asignación y elimina valores que violarían restricciones.

🔗 Consistencia de Arco (AC-3)

Cuando se elimina un valor de un dominio, el cambio se propaga por todos los arcos de restricción conectados.

⚠️ Thrashing: ocurre cuando el algoritmo redescubre una y otra vez las mismas inconsistencias.

🎯 Principio Fail-First

Asignar primero la variable más restringida (la que tiene menos valores viables).

Concentra el esfuerzo de poda cerca de la parte superior del árbol, donde tiene mayor impacto.

📊 Ordenación de valores

Cuando se busca una sola solución, intentar primero el valor que deja más opciones disponibles.

⏪ Backjumping dirigido por conflictos

Identifica qué decisión anterior causó el fallo actual y retrocede directamente hasta ella, saltándose decisiones intermedias irrelevantes.

📜 Perspectiva histórica

  • Stallman y Sussman: dependency-directed backtracking
  • Gaschnig: primer algoritmo explícito de backjumping
  • Dechter: algoritmo basado en grafos
  • Prosser: algoritmo CBJ

📝 Backmarking

Recuerda dónde fallaron las pruebas de consistencia anteriores para evitar repetir verificaciones.

Mantiene dos tablas:

  • Variable más temprana en conflicto con cada asignación
  • Variable más temprana que cambió de valor desde la última visita

No poda el espacio, pero reduce verificaciones de consistencia.

9. El Problema de las N Reinas

Colocar n reinas en un tablero de n × n sin que se amenacen entre sí.

  • Espacio de soluciones: {1, 2, 3, …, n}ⁿ
  • Probar todos los vectores implica nⁿ casos
  • Si las reinas deben estar en columnas diferentes: baja a n!

10. Conclusión

La búsqueda con vuelta atrás resuelve problemas de satisfacción de restricciones y de optimización combinatoria construyendo soluciones por etapas y podando grandes porciones del espacio de búsqueda en cuanto detecta una inconsistencia.

Permite trabajar con memoria lineal, aunque su peor caso siga siendo exponencial.

Su rendimiento práctico depende de qué tan pronto se identifican los fracasos, y por eso:

  • Propagación de restricciones
  • Heurísticas de ordenación
  • Retroceso inteligente
  • Backmarking

El paradigma elegir, explorar y deshacer sirve de base común para problemas muy distintos, desde acertijos hasta la verificación de hardware y software.
